# 聊天记录可视化（第一代）

自创的聊天记录保存项目，目标用于网络聊天历史时刻的回忆留存，以防止磁盘清理或聊天软件服务器清理导致的回忆丢失。

把 `数据文件` 目录里的聊天记录，用接近常用聊天软件的界面显示出来：
默认视角的发言靠右、绿色气泡，其它发言靠左、白色气泡；
聊天中的附件以按钮形式出现在气泡内，点击后在右侧栏或独立弹窗中浏览。

**第一代只做浏览，不做任何修改。** 界面上没有输入框、没有编辑入口，
聊天正文按原样渲染（包括换行、emoji、尖括号等特殊字符），
因此不存在“保存时改动原始记录”的风险。

## 运行

```bash
python main.py
```

依赖：

| 依赖 | 是否必需 | 说明 |
| ---- | ---- | ---- |
| Python | 必需 | 建议 3.8 及以上 |
| PyQt5 | 必需 | 界面框架，开发环境使用 5.15.10 验证 |
| markdown | 可选 | 用于把 `.md` 附件渲染成带表格的富文本；缺失时自动退化为纯文本显示 |

## 代码分工

`main.py` 只保留最简调用结构，所有调度都在驱动库内部完成：

```python
def main():
	应用实例 = PyQt5.QtWidgets.QApplication(sys.argv)
	聊天元数据   = 驱动库.读取聊天记录元数据()
	聊天显示窗口 = 驱动库.聊天记录可视化窗口(聊天元数据)
	聊天显示窗口.show()
	sys.exit(应用实例.exec_())
```

驱动库各模块的职责：

| 模块 | 职责 | 主要对外内容 |
| ---- | ---- | ---- |
| `基础工具.py` | 找路径、读文件，永不抛异常 | `读取聊天记录元数据()`、`读取文本()`、`读取JSON()` |
| `数据结构.py` | 把 JSON 转成界面对象，负责全部缺字段回退 | `数据仓库`、`会话`、`消息`、`附件`、`用户` |
| `会话列表.py` | 左侧列表、菜单式分隔符、折叠分组展开与收起 | `会话列表侧栏`、`会话行部件` |
| `附件面板.py` | 附件浏览：文本、Markdown、图片 | `附件侧栏`、`附件弹窗`、`附件内容视图` |
| `消息气泡.py` | 单条消息的气泡控件 | `气泡部件`、`attachmentClicked` 信号 |
| `聊天窗口.py` | 主窗口组装与交互 | `聊天记录可视化窗口`、`消息滚动区` |

`聊天记录可视化窗口(聊天元数据, 数据目录=None)` 的第一个参数既可以是元数据字典，
也可以是元数据 JSON 的路径；第二个参数用于把数据目录换到别处（默认使用项目内的 `数据文件`）。

## 界面说明

* **左侧会话列表**：按 `聊天记录元数据.json` 中 `所有消息记录` 的顺序列出会话，点击即可切换；
  当前选中的会话带浅灰底与左侧绿色强调条，鼠标悬停时整行变亮。
* **折叠对话分组**：取值 `折叠` 的会话默认被收进列表底部的“折叠对话”分组，
  与普通对话之间用一条菜单分隔符风格的水平细线隔开。
  点击分组标题即可展开或收起：收起时标题右侧箭头朝下 `▼`（表示可向下展开），
  展开时箭头朝上 `▲`（表示可收起）。
  折叠只影响会话列表要显示多少条，展开后的折叠对话与普通对话完全一样；
  收起分组不会影响正在浏览的会话。
* **气泡区**：`默认视角` 的那一方靠右显示、气泡为微信绿 `#95EC69`；其余发言人靠左、气泡为白色。
  三人及以上的会话会自动给他人消息标注发言人名称。
* **附件按钮**：气泡内的胶囊按钮，形如 `📄 小方个人信息` / `🖼 小方照片`。
  文本附件按纯文本显示，`.md` 附件渲染成富文本，图片按右栏宽度自动等比缩放。
* **右侧附件栏**：点击附件按钮出现；再次点击同一个附件、点“关闭”或按 `Esc` 收起；
  点“独立窗口”可把当前附件放到单独的弹窗中查看。原文件缺失时会给出提示并显示占位内容。
* **气泡宽度**：气泡最大宽度固定为聊天区可视宽度的 **50%**（`聊天窗口.py` 里的 `气泡宽度比例`）；
  短句保持自己的自然宽度、不会被硬拉宽，长句撑到 50% 之后才换行。
  短句宽度按“排成一行真正需要的宽度”算：先用排版引擎量一次（`估算正文宽度()`），
  再按 `消息气泡.py` 里的 `宽度试探步长` 往上试到确实不换行为止（`测量正文自然宽度()`），
  所以 emoji 这类改用彩色字体渲染、比估算更宽的字符，也不会被挤到下一行；
  仍然偏紧可以调大 `换行余量` 或 `宽度试探上限`。
  缩放窗口、拖动分隔条、打开右侧附件栏都会触发重算：`聊天窗口.py` 里的 `消息滚动区`
  在可视宽度变化时发出 `viewportWidthChanged` 信号，窗口收到后逐条调用气泡的 `设置气泡宽度()`。
* **滚动行为**：切换会话后自动滚动到最新一条消息。

## 数据格式

所有文件均为 UTF-8（无 BOM），字段缺失时一律走占位数据，不会因为少一个字段就报错。

### 聊天记录元数据.json

| 字段 | 类型 | 说明 |
| ---- | ---- | ---- |
| `所有用户` | 字符串数组 | 发言者名称清单，仅在 `所有用户.json` 缺失时作为补充 |
| `所有附件` | 字符串数组 | 附件名称清单（展示用，真正的附件信息在 `所有附件.json`） |
| `所有消息记录` | 对象 | `"会话键名": "折叠"` 或 `"不折叠"`；键名同时是 `聊天信息数据` 下的文件名 |
| `附件引用` | 对象 | `"会话键名": [附件名称, ...]`，当消息本身没写附件时作为兜底 |

列表顺序就按 `所有消息记录` 的书写顺序：非 `折叠` 的会话排在上面，
取值为 `折叠` 的会话被收进底部的“折叠对话”分组（分组内部同样保持书写顺序）。
除 `折叠` 以外的任何取值都按“不折叠”处理。

### 发言者数据/所有用户.json

| 字段 | 类型 | 说明 |
| ---- | ---- | ---- |
| `名称` | 字符串 | 发言者名称，与聊天记录中的 `发言者` 对应 |
| `头像` | 字符串 | `发言者数据` 目录下的图片文件名 |
| `注释` | 字符串 | 可选，仅供人看 |

名称为 `(default)` 的条目是占位头像，其它条目缺失时用它补全。

### 聊天附件数据/所有附件.json

| 字段 | 类型 | 说明 |
| ---- | ---- | ---- |
| `名称` | 字符串 | 聊天记录 `附件` 里引用的名字，如 `txt_小方个人信息` |
| `文件` | 字符串 | `聊天附件数据` 目录下的真实文件名，如 `小方个人信息.txt` |
| `类型` | 字符串 | 可选，`fig` 表示图片、`txt` 表示文本；缺失时按扩展名推断 |
| `注释` | 字符串 | 可选，仅供人看 |

**附件的两种写法都支持**：既可以写登记表里的 `名称`（如 `txt_小方个人信息`），
也可以直接写真实文件名（如 `小圆个人信息.md`）——`测试聊天3` 与 `测试聊天4` 分别演示了这两种写法。
按钮文字会自动去掉 `txt_`、`png_` 一类前缀。

### 聊天信息数据/某会话.json

| 字段 | 类型 | 说明 |
| ---- | ---- | ---- |
| `聊天标题` | 字符串 | 顶部显示的标题，缺失时用文件名代替 |
| `默认视角` | 字符串 | “我”是谁：该发言者的消息显示在右侧，缺失时取第一条消息的发言者 |
| `聊天内容` | 数组 | 每条消息为 `{"发言者": ..., "发言内容": ..., "附件": [...]}` |
| `发言内容` | 字符串 | 原样显示，`\n` 换行会被保留 |
| `附件` | 字符串数组 | 可选，元素为附件的 `名称` 或 `文件` |

## 容错行为

| 情况 | 界面表现 |
| ---- | ---- |
| 发言者没登记在 `所有用户.json` | 先在 `发言者数据` 里找同名图片（`小三角.png` 就是这样找到的），找不到用 `(default).png` |
| 头像图片损坏或丢失 | 用灰色圆形文字头像占位 |
| 附件没有登记 / 引用名写错 | 记入“缺失附件”，按钮提示原文件缺失，内容用 `(default_txt).txt` 或 `(default_fig).png` 顶替 |
| 聊天记录文件不存在或不是合法 JSON | 该会话显示为空，不弹异常 |
| 元数据为空或读不到 | 窗口显示“没有可显示的聊天记录”，并提示检查元数据文件 |

## 常见改动

**新增一段聊天记录**（模拟“来自另一个账户 / 另一个驱动软件”的记录）：

1. 把记录放到 `数据文件/聊天信息数据/<会话名>.json`；
2. 若有附件，把文件放进 `数据文件/聊天附件数据/` 并在 `所有附件.json` 中登记；
3. 若有新发言者，把头像放进 `数据文件/发言者数据/`（登记到 `所有用户.json` 更规范，不登记也能显示）；
4. 在 `数据文件/聊天记录元数据.json` 的 `所有消息记录` 和 `附件引用` 中登记，界面会自动多出一个会话。

除元数据和文件名要求外，驱动库不关心记录来自哪个账户、哪个对象、哪个驱动软件。

## 编码与风格约定

* 所有文件使用 UTF-8（无 BOM）读写，不使用系统默认字符集处理中文；
* Python 缩进用 tab，变量与函数尽量用中文命名；
* 不使用 `import ... as ...`；`from ... import ...` 仅限自定义库内部，
  且只允许 `from . import 某模块` 这一种写法（驱动库内部全部使用相对导入，
  例如 `from . import 基础工具`，调用时写完整的 `基础工具.读取JSON(...)`）；
* `main.py` 属于使用方而不是库，仍保持 `import 驱动库` 并用完整名字调用
  （`驱动库.读取聊天记录元数据()`）；
* 唯一的例外是 PyQt 的技术限制：`pyqtSignal` 的名称必须能用 ASCII 编码，所以信号名为
  `attachmentClicked`、`closeRequested`；信号连接的槽函数统一用 lambda 薄封装，
  这样其余方法名仍可保持中文。

## 已知限制与后续设想

* 第一代没有时间戳、已读状态、群公告等真实聊天软件的附加信息，因为数据里没有这些字段；
* “折叠对话”的展开状态只在本次运行内有效，重新打开程序会回到默认收起；
  需要默认展开时把该会话的取值从 `折叠` 改成其它值即可；
* 附件目前是逐个查看，没有做“一次列出全部附件”的汇总面板；
* 长会话是一次性构建全部气泡，记录条数达到万级时建议改成按需加载；
* 如果后续要“修改并保存聊天记录”，建议另开一代实现，不要破坏当前这套只读渲染逻辑。
