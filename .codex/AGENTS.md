## 编码规则（必须遵守）

- 所有文件必须使用 UTF-8（无 BOM）编码打开和读写
- 严禁按二进制或默认字符集（如 GBK）处理中文字符
- 修改包含中文的代码时，禁止写入 \uXXXX 转义或 ? 占位符
- 如果发现乱码，立即报告错误并停止操作，不要擅自"修复"
- 每次文件修改前需要修改重新打开阅读文件，以免与用户修改冲突

# Python 脚本编写原则（视情况）
- 缩进用 tab
- 不准使用 from ... import ... 和 import ... as ... 若要引用请引用完整的变量名，除非是自定义库的编写
- 自定义库编写时 临时允许 from import 的使用，但仅限于“from . import 某条目”和“from .. import 某条目”，若需要更上级包/库的支持打申请
- 尽可能使用中文变量名
- 添加完善的注释，函数内约越 3 ~ 20 行添加一条
- 冒号后面一定要换行

# C 脚本编写原则（视情况）
- 缩进用 tab
- 不要把函数缩到一行
- 每个 if 或 else 都要接大括号，即使只有一行
- 大括号前换行
- case 相对 switch 缩进+1，case 里面的代码相对 case 缩进+1
- 指针格式星号跟着类型，如“int* int_pointer_var;”
- 注释尽量用“//”，用户可以保证编译器支持C99及以上编译成功
- 单代码行不要擅自换行，用户会自己调整，同时用户调好的换行若接口修改按照用户习惯组织该段代码（需要调整的一般不到一行）
